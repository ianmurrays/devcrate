# Ports are dialed from inside the container's network namespace

`devcrate forward` listens on the laptop's `127.0.0.1` and, for each incoming connection, opens an SSH exec channel to an Agent subcommand that enters the devcontainer's network namespace, dials the target there and pipes the bytes; with no devcontainer it dials on the VM. We chose this over publishing ports on the VM (`appPort`-style `-p 127.0.0.1:...`) and over SSH-forwarding to the container's IP because dev servers commonly bind `127.0.0.1` inside the container, which neither alternative can reach, and because publishing needs a container recreate whenever the port list changes. Dialing from inside also resolves `"host:port"` entries such as compose service names for free. The cost: one SSH channel per TCP connection, and the Agent needs root to join the namespace.
