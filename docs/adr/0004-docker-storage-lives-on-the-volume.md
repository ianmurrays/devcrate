# Docker storage lives on the persistent volume, not in a registry

The setup script points Docker's `data-root` and containerd's `root` at directories under `/var/lib/devcrate` on every `up`, so images, build cache and the devcontainer itself survive a Stop and resume is a `docker start`. We chose this over pushing the image (or a BuildKit registry cache) to the cloud's container registry because it needs no registry, no extra credential and no Provider change, and because a registry only speeds up the first `up`. Moving only `data-root`, as DevPod's DigitalOcean provider does, is not enough: Docker 29+ fresh installs use the containerd image store, which `data-root` does not cover, and devcrate reinstalls Docker on a fresh root disk at every resume. The costs: the volume must be sized for images (`volume_size`, default 50 GiB), the Agent must stop dockerd and containerd and unmount the volume before Self-stop, and since the devcontainer CLI never detects config changes, devcrate hashes the build inputs and recreates the container when they change.
