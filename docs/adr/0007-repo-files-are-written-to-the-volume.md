# Repo files are written to the volume, not linked from the tmpfs

`forward_repo_files` in the user config copies gitignored secrets, such as Rails' `config/credentials/*.key`, from the laptop clone into the same paths in the Environment's clone, as real files on the volume. They survive a Stop and are removed only by Delete. This breaks the pattern of `forward_files` and the signing key (ADR 0006), which stay on the tmpfs and are gone after a Stop. We chose this over symlinking from the clone to the tmpfs because the clone is mounted into containers that devcrate does not set up, such as a docker compose service, and those containers do not mount `/run/devcrate/creds`, so the symlinks would not resolve exactly where the files are needed. A secret on the volume is no wider an exposure than ADR 0005 already accepts: the repo runs as root on its VM and can read every forwarded secret. As with every forwarded secret, only the user config can ask for these files, never `.devcrate.toml`.
