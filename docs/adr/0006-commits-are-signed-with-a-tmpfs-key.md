# Commits are signed with a dedicated key on the tmpfs, not through the forwarded agent

When the user config sets `git_signing_key`, devcrate forwards that private key to the VM's tmpfs, next to the other forwarded secrets, and points the Environment's git at it. A private key leaves the laptop. We chose this over signing through the forwarded SSH agent, which keeps every key on the laptop, because the forwarded agent refuses connections while nobody is connected, and commits made then (an agent running under a Keep-alive, a lifecycle hook) must be signed too. To limit the cost, the key is meant only for signing: it is registered on GitHub as a signing key, not an authentication key, so a leaked copy can sign as the user but cannot push. The key never touches the volume, so it is gone after a Stop. Signing settings are written in system git config through an include of a file on the tmpfs, so a missing key gives unsigned commits instead of failed ones. As ADR 0005 already accepts for other forwarded secrets, anything running as root on the VM can read the key.
