# One Environment per worktree, named from the worktree

A repo can have several Environments, one per git worktree, so parallel work on different branches never shares a disk. The main worktree keeps the name from `name` in `.devcrate.toml` or the repo name, so existing Environments are unaffected; a linked worktree gets `<name>-<worktree dir basename>`. `devcrate up --name <name>` overrides both, and is written to `devcrate-name` in the worktree's own git directory so later commands in that worktree find the same Environment. We chose the worktree directory over the branch because branches get renamed and switched while the Environment lives on, and over requiring `--name` everywhere because the common case should need no configuration. The name file does not break ADR 0002: it records which name a worktree uses, not which Environments exist or their state, and on another laptop the derived name is the fallback. Changing this scheme later orphans already-named Environments, since Providers tag resources by name and an Environment cannot be renamed.
