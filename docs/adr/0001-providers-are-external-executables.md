# Providers are external executables with a JSON verb contract

A Provider is an executable named `devcrate-provider-<name>` that devcrate runs once per verb (`up`, `stop`, `delete`, `status`, `list`, `save-image`, plus a `self-stop` script copied to the VM), passing one JSON object on stdin and reading JSON from stdout. We chose this over a Go interface compiled into devcrate so a new cloud is a script wrapping that cloud's existing CLI (reusing its auth), not a change to devcrate. Unlike DevPod, the contract has no transport verb and no tunnel: devcrate always reaches the VM over plain SSH, which keeps Providers to a few lines each.

The credential the Agent needs for Self-stop comes back from the Provider, not from devcrate's knowledge of options: `up` may return a `self_stop_env` object, which devcrate writes over SSH to a root-only tmpfs file on every `up`, and which the `self-stop` script sources. This lets a Provider mint a credential scoped to the one instance it just created (Vultr: an IAM policy on `instance:<id>`), where a static option would have to reach every instance in the account (DigitalOcean's `droplet:delete`, which its Provider simply echoes back).

devcrate gets the `self-stop` script itself from the laptop, through a `self-stop` verb that prints `{"script": "..."}`, and copies it to the VM. When idle stop is on, devcrate runs this verb before `up`, and a Provider fails it when no Self-stop credential is configured, so `up` fails before creating anything.

Every request carries `base_name`, the repo's base Environment name, which labels the repo's Base image (ADR 0009). `save-image` saves the Environment's VM as that Base image and leaves the Environment Stopped; with `"check": true` it only validates that it can, changing nothing, and with `"delete": true` it deletes the Base image instead, touching no Environment. `status` returns the Base image `up` would boot from as `base_image` (`id` and `created`), omitted when there is none.
